<h2>分配是决策，设置是执行</h2>
<p>「四个 IP 怎么分配」是决策问题：哪个给谁用。「服务器网络设置」是执行问题：怎么让这些分配在机器上生效。两件事分开做，先定分配表，再动手配置。</p>
<p>先配置再想分配，结果是配完发现归属乱、规则对不上，只能推倒重来。</p>

<h2>先在纸上完成分配</h2>
<p>四个地址，写清：编号、用途、绑定对象、是否需要独立出口。四个字段填完，分配就定了。这一步花十分钟，能省掉后面几小时的返工。</p>
<p>如果暂时想不清「绑定对象」，就先按业务线分，别按设备分。设备会换，业务线相对稳定。</p>

<h2>服务器侧的三个动作</h2>
<p>一是把地址加到接口上。可以在主网卡上添加多个地址（别名方式），也可以为每个地址建一个虚拟接口。前者快，后者清晰。</p>
<p>二是补路由。多数系统加地址后会自动生成一条直连路由，但默认网关只有一条。要让某个地址作为源出网，需要为它指定路由或使用策略路由。</p>
<p>三是定策略。按来源、按用户或按标记，把流量导向指定地址。策略写在独立的表里，避免与主表冲突。</p>

<h2>三类写法的取舍</h2>
<p>别名地址：一条命令加一个地址，最快，但所有地址共享同一接口的队列，排障时不容易单独观察。虚拟接口：配置稍多，但每个地址的流量可以单独统计与限速。</p>
<p>策略路由：灵活度最高，规则数量随需求增长，写不好会影响性能。三种可以组合使用，比如虚拟接口加策略路由，是最常见的组合。</p>

<h2>命令层面的一个思路</h2>
<p>不管用什么系统，思路都是三步：把地址挂到接口上、告诉系统这个源地址走哪个出口、再让程序或规则选择源地址。三步对应三组命令，顺序不能乱。</p>
<p>执行顺序乱的典型表现是「地址有了但不通」。这时候不用怀疑地址，先查路由表里有没有对应条目。</p>

<h2>常见设置错误</h2>
<p>一是只在主网卡加地址，没做虚拟接口，结果无法按地址限速。二是忘了配网关，地址能通内网但不通外网。三是策略规则顺序写反，特例被通用规则吞掉。</p>
<p>四是程序不认源地址。前面三步都做对了，程序仍用默认地址出网。这一项要靠程序参数或策略标记解决，不能靠加地址。</p>

<h2>验证与归档</h2>
<p>逐地址验证出口，四个都要测。验证完把「地址—接口—用途—验证时间」写成表归档，作为后续变更的依据。</p>
<p>变更时要同步更新这张表。表与实际情况脱节，是后面所有混乱的起点。</p>

<h2>配置改完之后，第一件事是复验而不是庆祝</h2>
<p>网络配置有个特点：改一处可能影响别处。加了地址、改了策略之后，原本正常的那一组也可能被带偏。所以每次变更后都要把四个地址重新走一遍验证，而不是只看改动的那个。</p>
<p>复验花不了几分钟，但能挡住「改 A 坏 B」这类最难查的问题。等到用户报障再回头看，往往已经隔了一两天，现场信息也丢了。</p>
<h2>常见问答</h2>
<h3>一定要用虚拟接口吗？</h3>
<p><strong>答：</strong>不必须。但如果要按地址限速或单独统计，虚拟接口更方便。</p>
<h3>加了地址为什么还不通？</h3>
<p><strong>答：</strong>先查路由表有没有对应条目，再看策略规则是否匹配到。</p>
<h3>四个地址能限速吗？</h3>
<p><strong>答：</strong>能。按接口或按用户限速都可以，按接口更简单。</p>
<h3>改配置会不会断网？</h3>
<p><strong>答：</strong>有可能。建议先保留一条可用的管理通道，避免把自己锁在外面。</p>
